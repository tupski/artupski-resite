# Blueprint documentation generation - decisions

`docs/specs/BLUEPRINT-SPEC.md` defines the Blueprint evidence document but is
silent on the AI-powered *documentation set* generated from it. This note records
the reasonable, documented decisions taken so the behaviour is reproducible.

## Document set

| Document | Tier | Condition |
| :--- | :--- | :--- |
| `AGENTS.md` | Required | Always |
| `PRD.md` | Required | Always |
| `ARCHITECTURE.md` | Required | Always |
| `PLAN.md` | Required | Always |
| `UI-SPEC.md` | Required | Always |
| `ASSETS.md` | Required | Always |
| `TESTING.md` | Required (recommended) | Default on; suppress with `includeTesting: false` |
| `DATABASE.md` | Optional | `admin_requirements.entities.length > 0` |
| `API.md` | Optional | any `forms[].action_endpoint` is non-empty |
| `SECURITY.md` | Optional | auth type ≠ `none`, or protected routes/roles, or a `password` field |
| `DEPLOYMENT.md` | Optional | env variables, a non-`static_spa` target, or a detected runtime/framework/CDN |

- **D1 - TESTING.md**: the task brief lists it under required but marks it
  "optional but recommended". It is generated by default (so the required set is
  complete) and can be turned off explicitly.
- **D2 - relevance is evidence-driven**: optional docs are selected from real
  Blueprint fields only. An explicit `include` toggle wins over relevance; an
  explicit `exclude` wins over both.
- **D3 - required documents are never optional**: they cannot be suppressed
  except `TESTING.md` per D1.

## AI usage

- **D4 - narrative only**: the AI contributes a bounded `Summary (AI-assisted)`
  section (summary + ≤ 8 notes). All tables, token values, route lists, and asset
  inventories are generated locally so output is reliable even if AI is down.
- **D5 - per-document isolation**: an AI failure (unconfigured, network, schema,
  or token budget) never fails the run. The deterministic document is emitted and
  a bounded warning is recorded (`DOC_AI_UNAVAILABLE`, `DOC_PROMPT_TOO_LARGE`,
  `DOC_AI_EMPTY`, or the underlying AI error code).
- **D6 - token budget**: the prompt is pre-checked with `TokenBudgetManager`
  before any call; an oversized prompt is skipped with a warning. Payloads are
  per-document and cardinality-bounded (AI-SPEC §3.2).
- **D7 - untrusted data**: the payload is passed through
  `buildUserMessageContent`, so it is sanitized and wrapped in `<DATA_PAYLOAD>`
  exactly like every other AI call (AI-SPEC §4/§5).

## Wiring

- **D8 - no new persistence**: documents are generated in memory and returned.
  They are written to the generated project by the exporter/UI path, not by the
  Blueprint lifecycle. This keeps the Blueprint row/`blueprint.*` events unchanged.
- **D9 - no new worker / no Rust command**: like the other AI services this is a
  main-process TypeScript module; `WORKER_PROTOCOL_VERSION` is unchanged.
- **D10 - existing export events**: generation emits the existing
  `export.doc_generated` event (name + bytes only) so the UI can mirror progress
  without any new event taxonomy.
